# 演示录屏脚本

**总长 3 分 40 秒｜剪辑版 1 分钟（见文末）**

---

## 录屏前准备（这步别省）

妆造好了再开机。以下准备能省掉 80% 的重录：

### 1. 账号数据

用一个**有记忆的老账号**（效果最好）。需要预先造出这些数据：

| 数据 | 怎么造 |
|---|---|
| 昵称「麦小门」 | 三连问时填 |
| 生日 10/24（天蝎座，生日月） | 三连问时填 → 开场能说"明天你生日" |
| 忌口「香菜」 | 三连问时选标签 |
| 本命单品「麦麦鸡」 | 先正常点一次含麦麦鸡的单，确认下单 |
| 习惯「可乐去冰」 | 同上 |
| 情绪日记「10/23 烦躁」 | **把系统日期调到 10/23**，聊一次"我好烦啊"，然后调回 10/24 |
| 水逆状态 | 自动的（2026-10-22 至 11-11 是水逆期，10/24 正好第 3 天） |

> 💡 **调系统日期是造情绪日记最省事的办法**。
> 如果不想调，也可以在 `server/data/mcd.db` 里直接插一条 `mood_diary`。
> 但**别在录屏里现场造**——观众要看的是"它记得"，不是"我正在让它记"。

### 2. 环境

```bash
# 1. 确认服务在跑
curl https://your-domain.com/api/health
# → {"ok":true,"mcp":"reachable"}

# 2. 确认 MCP 通（否则会走离线兜底，虽然也不错但不如实时数据有说服力）
cd server && npx tsx scripts/mcp-smoke.ts <你的token>

# 3. 浏览器准备
#   - 用 Chrome，窗口 1440×900 或 1280×800
#   - 缩放 100%（别用 125%，字会糊）
#   - 关掉所有插件、书签栏（Ctrl+Shift+B）
#   - 开一个干净的用户资料
#   - 提前登录过一次，确认 Cookie 有效
```

### 3. 录制设置

- **OBS** 或系统自带（macOS `Cmd+Shift+5` / Windows `Win+Alt+R`）
- 分辨率 1920×1080，30fps 足够
- **一定要录麦克风**（人声是这个演示的一半）
- 鼠标高亮插件（可选，但强烈建议 —— 观众需要知道你在点哪）

### 4. 录制前清空

- 聊天区清空（刷新页面即可，记忆不会丢）
- 关闭其他标签页
- 手机端演示提前在真机上打开并登录好

## 分镜脚本

### 0:00–0:20 ｜ 痛点（20 秒）

**画面**：桌面，浏览器还没打开。屏幕上打一行大字，或对着 web 上的登录页说。

**台词**：

> 「现在的点餐助手，只会算账。
> 你说『4 个人 150 块不辣』，它给你凑一单——这个它做得挺好。
> 但你要是说『我好烦啊』呢？
> 它要么反问你『请问需要点什么』，要么给你推爆款。
>
> **可是人是带着情绪去吃饭的。**
> 烦的时候想吃辣，累的时候想吃热乎的，低落的时候不想被人玩梗。
> 这些信息，点餐系统里没有，但对话里有。」

**要点**：
- 语速稍快，别拖
- 「我好烦啊」这句要说得像真的烦

---

### 0:20–0:50 ｜ 登录：Token 一贴，它认识你了（30 秒）

**画面**：打开 `https://your-domain.com`，显示登录页（红色渐变背景 + 白色卡片）。

**操作**：鼠标指向输入框，粘贴 Token（`type="password"` 会自动遮蔽）。

**台词**：

> 「登录只有一个动作：粘贴你的麦当劳 MCP Token。
> 不用注册、不用授权跳转、不用填手机号。
>
> **Token 就是身份。**
> 它被 AES-256 加密存在服务端，浏览器里只有一个 httpOnly Cookie，前端代码读不到。
> 这也意味着——AI 是拿**你自己的麦当劳会员账号**在操作，所以它能直接帮你下单。」

**操作**：点「连接麦当劳，开始」。

**画面**：如果是新账号会进三连问；如果是老账号直接进聊天页。

> 💡 **用到三连问的画法**（如果是新号）：
> 问「我该怎么叫你」→ 填「麦小门」
> 问生日 → 选日期 → **立刻出现「天蝎座。懂了，难怪你爱吃辣。」**
> （这句要留 1 秒给观众看清）
> 问忌口 → 选「香菜」→ 点「开始聊天」

**台词（三连问时补一句）**：
> 「三个问题，都是为了后面它能少问我几次。」

---

### 0:50–1:50 ｜ 场景① 情绪场景（60 秒，核心）

**画面**：聊天页。左侧聊天区，右侧记忆面板（5 张卡片）。

**操作**：先让鼠标扫一下右侧记忆面板（2 秒），让观众看见"它记着这么多东西"。

**台词**：
> 「右边是它的记忆，五层：静态档案、口味画像、习惯数据、情绪日记、仪式记忆。
> 现在我把这些全忘掉，只说四个字。」

**操作**：输入「我好烦啊」→ 回车。

**画面**：进度气泡出现 → stage 文案依次变化（"让我想想你想吃什么…" → "翻了翻节气和你星座的运势…" → "正在替你看菜单…" → "顺便翻了翻你的优惠券…" → "给你写点人话…"）→ 打字机效果出现开场白 → 完整气泡展开。

**台词（跟着 stage 说，别念 stage 文案本身）**：
> 「注意它没有反问我『请问您需要点什么』。
> 它在同时读三样东西——
>
> 第一，今天是**霜降**第二天，秋末了，该贴秋膘；
> 第二，**水逆第 3 天**（我记得，你 22 号就开始跟我抱怨代码了）；
> 第三 —— 我的生日是**明天**。」

**画面**：菜单展开。

**台词（指着菜单）**：
> 「它给了一单叫『水逆急救单』：
> 新地——甜度抵消 30% 烦躁；
> 麦辣鸡翅——烦就要吃辣，物理发泄；
> 冰鲜柠檬水，**去冰**——因为我上次说过；
> 热可可——霜降了，热乎的才对。
>
> 券后 39.5，原价 50。热量 720 卡。
> **每一样都有理由，理由里都有我的数据。**」

**画面**：滚动到金句框。

**台词（念金句，慢一点）**：
> 「『宇宙没善待你，但优惠券有。上周四你烦的时候吃了麦麦鸡说治愈
> ——这次加个热可可，霜降嘛，麦门。』
>
> **这句是全篇最重要的一句。**
> 它在用我的历史情绪数据。上周四我也烦，那天吃了麦麦鸡，我说了句「治愈」，
> 它记住了。这种话没法现编，只能说给一个认识你的人听。」

**画面**：鼠标扫一下右侧「情绪日记」卡片（应该刚多了一条今天的记录）。

**台词**：
> 「看，记忆面板同步更新了。」

---

### 1:50–2:40 ｜ 场景② 明确指令（50 秒）

**台词（转场）**：
> 「当然，正常需求它也能接。这个场景是评委最容易验证的。」

**操作**：输入「明天中午4个人，预算150，有人不吃辣」→ 回车。

**画面**：菜单展开。

**台词（指菜单）**：
> 「4 人餐、¥150 以内、1 份免辣。
>
> 巨无霸套餐 ×2，板烧鸡腿堡套餐不辣版 ×1——**给不吃辣的同学**；
> 麦麦鸡 ×1 微辣——顺手带上我的本命；
> 玉米杯 ×4。
>
> 合计 **145.5**，预算内，剩余 4.5。」

**台词（重点说预算这里）**：
> 「这里有个细节：剩的 4.5 它说『够加一个圆筒』。
> 这不是凑单——预算是**硬约束**，装箱算法会跳过放不下的商品继续找便宜的，
> 所以一分钱不会超。剩下的是主动加价值。
>
> 还有，'有人不吃辣'被理解成了**一份免辣**，不是整单免辣。
> 这两个区别挺大的。」

---

### 2:40–3:20 ｜ 场景③ 老用户回归（40 秒，情感高点）

**台词（转场，语气放缓）**：
> 「最后一个场景，是我用了一段时间之后再回来。」

**操作**：输入「我又来了」→ 回车。

**画面**：开场白出现。

**台词（念开场白，这四句是全文最有说服力的）**：
> 「我什么都没说。它说：
>
> 『哟，麦小门。三天不见，我可都记着呢——
> 上周四你烦躁，麦麦鸡治好了你；
> 你的可乐永远去冰；
> 还有，明天你生日。』
>
> **三件事，全是跨会话记忆。**
> 它给了一单『寿星专属』：圆筒冰淇淋（长寿冰淇淋，提前一天开吃）、
> 麦麦鸡 ×2、可乐去冰。」

**画面**：鼠标扫右侧记忆面板。

**台词（收）**：
> 「**用得越久它越懂你**。
> 这话别的助手说不出，因为它们没记性。
>
> 而这个记忆，你随时可以在记忆管理页删掉 —— 待会儿演示。」

---

### 3:20–3:50 ｜ 下单（30 秒）

**操作**：点「确认下单」→ 出现确认条（「「寿星专属」¥33.0 · 留仙洞店 · 自取，确认建单？」）

**台词**：
> 「下单前它会复述一遍：什么单、多少钱、哪家店、怎么取。
> 这一步不能省——**建单是写操作，得让用户看清再点**。」

**操作**：点「确认」→ 支付卡片出现（金额 + 门店 + 「点击去付款」）

**台词（这里要强调安全边界，语速放慢）**：
> 「建单成功，返回一个支付链接。
>
> 这里有一条不可逾越的线：
> **付款必须由用户本人完成。** Agent 只负责建单，不碰钱。
> 代码库里没有任何自动支付、代付的路径——这是麦当劳平台的责任设计，
> 也是我们守的底线。」

**画面**：状态文案自动变化（等你付款 → 收到钱了，正在准备 → 正在为你出餐… → 可以取餐了 🍟）

**台词**：
> 「状态会自动更新，三秒一次，三十秒后退到十秒一次，最多轮询五分钟。
> 页面切到后台会暂停——省请求，也是礼貌。」

---

### 3:50–4:00 ｜ 收尾（10 秒）

**画面**：停在聊天页，或切到 GitHub 仓库首页。

**台词**：
> 「一个 Token，一次粘贴，它就能记住你。
>
> 单机可部署，零外部依赖，代码全开源。
> 仓库地址在简介里。谢谢。」

## 剪辑版（1 分钟，只留高光）

如果只能投 1 分钟，按这个顺序剪：

| 时间 | 内容 | 时长 |
|---|---|---|
| 0:00–0:08 | 痛点：「现在的助手只会算账…你说我好烦啊，它反问你请问需要点什么」 | 8s |
| 0:08–0:16 | 登录：Token 一贴，进聊天页 | 8s |
| 0:16–0:34 | **场景① 完整回复**（开场白 + 菜单扫一遍 + 金句） | 18s |
| 0:34–0:42 | **场景③ 老用户回归开场白**（「哟，麦小门。三天不见…」） | 8s |
| 0:42–0:52 | 下单：确认条 → 支付卡片 → 「付款由你完成」 | 10s |
| 0:52–1:00 | 收尾一句话 + 仓库地址 | 8s |

**剪辑原则**：
- 场景②（4人150）**不放进 1 分钟版**——它是最不独特的一个，长版留着给评委看
- 金句必须完整念完，不能截断
- 不要加背景音乐盖住人声
- 不要做花哨转场，直接硬切

## 备用：如果 MCP 挂了怎么办

录屏时如果 MCP 不通，会走离线兜底菜单并在界面上标「参考菜单，实时价格待确认」。

**两个选择**：

1. **等**（推荐）：`npx tsx scripts/mcp-smoke.ts <token>` 确认恢复了再录
2. **照录，但主动说明**：
   > 「现在麦当劳那边连不上，它走了离线兜底菜单，界面上明确标了『参考菜单，实时价格待确认』。
   > 注意它没有假装拿到实时数据——这是设计的一部分。」
   >
   > 这其实是个加分项（诚实降级），但需要你主动点出来，否则观众会以为是 bug。

---

## 备用：如果 LLM 挂了怎么办

回复会走模板兜底，菜单和价格**完全不受影响**（因为菜单从来不是 LLM 生成的），
只是措辞朴素一些。

**这也是个可以主动展示的点**：
> 「菜单是规则算出来的，不是模型生成的——所以模型挂了菜单还是对的。
> 模型只负责把理由说得好听一点。」

## 检查清单（录完必看）

- [ ] Token 输入框在画面里是遮蔽的（没有露出明文）
- [ ] 没有出现服务器 IP、真实域名以外的内部地址
- [ ] 三个场景的菜单数字都清晰可读（别糊）
- [ ] 金句完整念完了
- [ ] 「付款由你完成」这句话说清楚了
- [ ] 结尾有仓库地址
- [ ] 时长 3–4 分钟（不要超）
- [ ] 人声清晰，没有环境噪音
- [ ] 没有卡顿、没有 loading 转圈超过 2 秒的画面（剪掉）
- [ ] 鼠标点击位置观众能看清
