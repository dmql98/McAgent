## 三、本任务范围

### 3.1 `server/src/services/knowledge.service.ts` —— 纯函数模块

**零 IO、零依赖、纯函数**（只在最后一步需要一个 `now: Date` 参数，方便测试注入）。

#### (a) 节气表
24 节气 → 日期区间 + 食物意境 + 推荐策略。数据结构：
```ts
interface SolarTerm {
  name: string;          // "霜降"
  startMonth: number; startDay: number;  // 起始日（含）
  endMonth: number; endDay: number;      // 结束日（含）
  imagery: string;       // 意境，如"秋末昼夜温差大，人要贴秋膘"
  strategy: string[];    // 策略标签，如 ["温热","高碳水","高满足感"]
  keywords: string[];    // 可推荐的品类关键词，如 ["热饮","板烧","可可"]
  blurb: string;         // 一句可直接用的节气文案
}
```
必须覆盖全部 24 个节气。日期用平年近似（节气每年浮动 1-2 天，够用）。
**注意跨年边界**：小寒/大寒在 1 月，冬至在 12 月，函数要能正确处理"今天是 1 月 5 日 → 小寒"。
导出 `getSolarTerm(date: Date): SolarTerm`。

给出这几个关键节气的**具体内容**（其余按合理常识写）：
- 霜降（10/23–11/6）：贴秋膘，温热高碳水，热可可/板烧/浓汤
- 立冬（11/7–11/21）：进补开局，热量正当化
- 冬至（12/21–1/4）：暖冬套餐，仪式感最强
- 小暑（7/6–7/21）：以热制热，冰品正当化
- 立秋（8/7–8/22）：贴秋膘前奏，第一杯热饮

#### (b) 星座库
12 星座 → 日期区间 + 食物性格 + 月度策略。数据结构：
```ts
interface StarSign {
  name: string;          // "天蝎座"
  startMonth: number; startDay: number;
  endMonth: number; endDay: number;
  personality: string;   // 食物性格，如"爱恨分明，要么清汤要么爆辣"
  strategy: string[];    // 策略标签
  birthdayTactic: string;// 生日月专属玩法，如"圆筒当长寿冰淇淋"
}
```
导出：
- `getStarSign(date: Date): StarSign`（按生日推算）
- `isBirthdayMonth(starSign, today): boolean`
- `getMercuryRetrograde(today: Date): { active: boolean, dayIndex: number, phase: "start"|"mid"|"end" } | null`
  —— 水逆区间**用静态表写死 2026 全年 3–4 段**（如 2026-02-26 至 2026-03-20、2026-06-29 至 2026-07-23 等，
  你可以按占星常识给出合理区间，**在代码注释里标注"演示用静态表，非天文精确"**）。
  水逆期间策略：稳住型（熟悉口味、不冒险）。

#### (c) 情绪策略
6 类基本情绪 → 口味策略：
```ts
type Mood = "烦躁" | "疲惫" | "低落" | "开心" | "平淡" | "庆祝";
```
每类给：`{ tasteStrategy: string[], avoid: string[], warmth: "温和"|"正常"|"俏皮", sampleHook: string }`
- 烦躁 → 甜 + 辣 + 冰（物理发泄），避免"清淡/健康"说教
- 疲惫 → 高碳水 + 热饮 + 提神，避免复杂选项
- 低落 → **温和模式**，禁玩梗，温暖碳水 + 甜，sampleHook 要真诚不俏皮
- 开心 → 加料 + 大份 + 分享感
- 平淡 → 尝鲜 + 小惊喜
- 庆祝 → 仪式感 + 圆筒/甜品 + 大份

导出 `getMoodStrategy(mood: Mood)`。

#### (d) 时段判定
导出 `getTimeSlot(date: Date): "早餐"|"午餐"|"下午茶"|"夜市"|"深夜"`
（边界：5-10 早餐、11-14 午餐、14-17 下午茶、17-22 夜市、22-5 深夜）

#### (e) 策略合成（这个函数是 orchestrator 的主要入口）
```ts
interface StrategyContext {
  solarTerm: SolarTerm;
  starSign: StarSign | null;         // 用户没填生日时为 null
  birthdayMonth: boolean;
  retrograde: {...} | null;
  mood: Mood | null;
  timeSlot: string;
  taboo: string[];                   // 用户忌口，必须参与过滤
}
export function composeStrategy(input: {
  now: Date; birthday?: string; mood?: Mood | null; taboo?: string[];
}): StrategyContext
```
以及一个给 LLM 用的摘要函数：
```ts
export function strategyToPrompt(ctx: StrategyContext): string
```
输出一段自然语言（不是 JSON），给 system prompt 的 L3 层直接用。必须说清"为什么这么推荐"，
让 LLM 能"点明出处"。

### 3.2 `server/src/services/memory.service.ts` —— 记忆读写

**注意：本任务不碰数据库。** memory.service 只做「JSON 对象的内存操作 + 摘要去重」，
真正的持久化由调用方（M4 orchestrator）传入读写接口。

设计成**依赖注入**的纯逻辑：
```ts
export interface MemoryStore {
  load(userId: string): UserMemory | null;
  save(userId: string, memory: UserMemory): void;
}
```
你实现一个 `MemoryService` class，构造函数收 `MemoryStore`；另外给一个
`class InMemoryStore implements MemoryStore` 供单测用（Map 实现）。
**不要写 better-sqlite3 的版本**——那是 M4 接线时的事，你只需保证接口就位。

要提供的方法：
- `snapshot(userId): MemorySnapshot` —— 给 LLM 的记忆快照（精简版：昵称/星座/忌口/口味标签/
  近3条情绪日记/水逆状态/常点Top3），要控制长度（估算 token < 400）
- `appendFact(userId, key, value)` —— 通用追加，同 key 覆盖（去重）
- `updateTaste(userId, patch)` —— 口味画像增量合并
- `addMoodEntry(userId, entry)` —— 情绪日记追加，**同一天同一 mood 只保留一条**（覆盖）
- `recordOrder(userId, order)` —— 下单后更新 habits（常点单品 Top5 重排序、预算区间滑动、常去门店）
- `updateRitual(userId, ritual)` —— 节气/水逆/生日仪式记忆
- `deleteEntry(userId, key)` —— 删除某条记忆（供 `/api/memory/:key` 用）
- `toCards(userId)` —— 转成前端记忆面板的 5 张卡片结构（对照 demo 的 aside.memory）

**摘要去重规则**（重点，PRD §11 风险里点名了）：
- `taste.topItems` 最多 5 个，按出现频次排序，同频按最近时间
- `moodDiary` 最多保留 30 条，超出裁剪最旧的
- `habits.orders` 最多 50 条
- 任意字符串字段超过 200 字符截断
- 整体 JSON 序列化后超过 8KB 时，裁剪 moodDiary 到 10 条（并记一条 warn 日志）
- `version` 字段每次 save 自增（乐观锁用）
