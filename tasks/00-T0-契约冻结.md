## 一、项目背景（你需要知道的全部）

「麦门知己」是一个麦当劳点餐 Agent。用户说任何一句话（可以是情绪化的"我好烦啊"，
也可以是明确的"明天中午4个人150块有人不吃辣"），系统解析后结合节气、星座、用户长期记忆，
输出一份完整菜单 + 情绪价值拉满的回复，登录后可直接下单。

技术上是一个前后端分离的单体应用，自部署在个人服务器上：
- 前端：纯静态 HTML/CSS/JS（无构建链），已有样式定稿 demo
- 后端：Node.js 22 + Express 5 + TypeScript
- 数据库：SQLite（better-sqlite3，WAL）
- 外部依赖：麦当劳 MCP（https://mcp.mcd.cn，Streamable HTTP，30+ 工具）+ 一个 OpenAI 兼容的 LLM

核心业务流水线（六层，前端的进度提示要跟这个对齐）：
⓪ 身份层：校验 JWT → 加载用户记忆
① 多维意图解析：显式约束（人数/预算/忌口/时段）+ 情绪信号（6类）+ 隐式上下文（节气/星座/记忆）
② 知识引擎：节气历 × 星座库 × 时段感 → 推荐策略
③ MCP 现实校准：查真实菜单/特制项/营养/优惠券/算价
④ 输出生成：懂你开场 + 完整菜单卡片 + 情绪收尾（结构化 JSON，不是 markdown）
⑤ 交易闭环：确认 → create-order（返回支付链接，用户自己付款）→ 记忆更新落盘

### 1. `docs/contract.md` —— 人读的契约文档
逐条写清楚，作为其他所有开发会话的依据：

- **API 清单**：方法、路径、请求体、响应体、错误码。至少覆盖架构文档 §5 的全部接口：
  `POST /api/auth/login`、`POST /api/auth/logout`、`DELETE /api/auth/unbind`、`GET /api/me`、
  `PUT /api/profile`、`POST /api/chat`、`POST /api/orders/confirm`、`GET /api/orders/:id`、
  `GET /api/memory`、`DELETE /api/memory/:key`、`GET /api/health`
- **统一错误响应格式**：`{ error: string, message: string, retriable?: boolean }`，
  错误码枚举至少包含 `TOKEN_INVALID`、`RATE_LIMITED`、`MCP_DOWN`、`LLM_FAILED`、
  `GUEST_LIMIT_REACHED`、`ORDER_CONFLICT`、`UNAUTHORIZED`
- **SSE 事件契约**（`POST /api/chat` 的流式输出）：
  - `event: stage` → `{ stage: "intent"|"knowledge"|"menu"|"coupon"|"compose", text: string }`
    （text 是给用户看的中文进度文案，如"正在替你看菜单…"）
  - `event: delta` → `{ text: string }`（开场白的打字机增量，可选）
  - `event: reply` → 完整回复 JSON（见下一节）
  - `event: done` → `{ chatId: string }`
  - `event: error` → 统一错误体
- **回复 JSON Schema**（这是前端渲染的唯一输入，必须逐字段定义）：
  ```
  {
    hook: string,                  // 懂你开场，2-3句
    meta: {
      store: string,               // 门店名
      slot: string,                // 时段/取餐时间描述
      title: string                // 菜单标题，如"你的「水逆急救单」"
    },
    menu: [{
      name: string,
      spec: string,                // 规格/数量/特制，如 "×2 · 去冰"
      why: string,                 // 推荐理由，可空
      price: number,               // 单价或该项小计（明确是哪个）
      originalPrice?: number
    }],
    total: number,                 // 券后实付
    original?: number,             // 原价合计
    budget?: { limit: number, ok: boolean, remaining: number },  // 有预算约束时才有
    nutrition?: string,            // 热量一句话
    quote: string,                 // 情绪收尾金句
    actions: string[],             // ["confirm","refine","reorder"] 子集
    upsell?: "login"               // 访客模式专属标记
  }
  ```
- **记忆数据结构**（对应架构 §6）：
  `profile{nickname,birthday,starSign,taboo[]}`、`taste{sweetness,spicy,temp,topItems[],customs[]}`、
  `habits{orders[],budgetRange,usualSlots[],usualStore}`、`moodDiary[{date,mood,trigger,recommended,feedback}]`、
  `rituals{lastSolarTerm,m mercuryRetrograde,birthdayReminder}`
- **MCP 工具调用约定**：工具名、入参、哪些走缓存（只读）、哪些永不走缓存（create/cancel/bind）

### 3. `web/mock.js` —— 前端开发用的假数据层
- 导出 `mockApi` 对象，方法签名与真实 API 完全一致：`login/logout/me/updateProfile/chat/confirmOrder/orderStatus/getMemory/deleteMemory`
- 实现**三个已定稿的演示场景**，直接从 `demo/index.html` 里搬运视觉所需的数据结构，但转成上面的回复 JSON 格式：
  1. 输入"我好烦啊" → 情绪场景（霜降 + 天蝎座 + 水逆第3天 + 记忆回钩，菜单含新地/麦辣鸡翅/柠檬水去冰/热可可，券后 39.5 原价 50.0，720kcal）
  2. 输入"明天中午4个人，预算150，有人不吃辣" → 明确指令场景（巨无霸套餐×2 + 板烧不辣×1 + 麦麦鸡×1 + 玉米杯×4，合计 145.5，预算内剩余 4.5）
  3. 输入"我又来了" → 老用户场景（圆筒 + 麦麦鸡×2 + 可乐去冰，券后 33.0 原价 40.5）
  4. 其他任何输入 → 兜底场景（返回一个合理的默认菜单，不让前端白屏）
