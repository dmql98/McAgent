00能否并行开发？—— 能，三条流水线 + 契约先行

并行前提：契约先行。§5 API 设计与回复 JSON Schema 已在架构文档冻结，前端不需要等后端——先用 mock.js 里的假数据把全部界面做完，后端好了切真实接口，改动只有一处 fetch 层。
流水线 A · 后端地基（红） M1 脚手架+登录 ──→ M3 MCP 网关 ──────→ M6 直下单 流水线 B · 智能层（蓝） M2 知识+记忆 ──→ M4 编排+LLM（gateway 用接口 mock，A 完成即切换） 流水线 C · 前端（绿） demo 组件化 ──→ mock 全界面 ──────→ M5 真实接线（等 M4 SSE 契约） 串行汇合点（不可并行的三处）： ① M4 编排 ← 需要 M2 的记忆快照 + M3 的 gateway（A、B 都完成） ② M5 接线 ← 需要 M4 的 SSE 事件格式定稿 ③ M6 下单 ← 需要 M3 gateway + M4 菜单快照
只有你一个人 + 我开发？「并行」体现为模块解耦推进：知识表、前端 mock 界面、schema 设计互不阻塞，可同批次交付；真正的串行只有集成测试阶段。
有队友？按流水线分工：A 给熟悉 Node/部署的人，B 给写 prompt/规则的人，C 给切页面的人。每条流水线内部任务无相互依赖，可放心并行。
泳道标记： A 后端地基 B 智能层 C 前端 S 串行集成

02怎么用这份计划

  • 单人开发（现状）：我按 A → B/C 交错推进：M1 脚手架完成后，M2（纯函数）与 M3（依赖 M1）可同批次交付，M5 的 mock 界面在等接口期间提前做；真正必须串行的只有 M4 集成、M6 下单、M7 收尾。
  • 多人开发：按泳道标记（A/B/C）认领，汇合点在 M4/M6；把本页放到服务器上，各自勾选实时可见进度。
  • 阻塞处理：某任务卡住就保持未勾选并在其行内备注原因——未完成任务即天然风险清单；M4/M6 未完成时 M7 的录屏兜底始终可用。
  • 进度持久化：勾选状态存浏览器 localStorage（key: mcd-soulmate-plan-v1），换设备/清缓存会重置——多人协作建议把本页部署到服务器各自勾选，或以本文件为模板复制多份。
