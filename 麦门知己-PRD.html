01项目概述

1.1 一句话定位

「麦门知己」：一个有记忆、懂情绪、知节气识星座的麦当劳点餐 Agent。 用户输入可以是明确的（"3 个人 100 块午饭"），也可以是纯情绪的（"我好烦啊"）， 系统同时解析三类信号，叠加节气与星座知识、调用用户长期记忆，最终输出一份完整菜单和一段情绪价值满满的回复。点餐只是它表达关心的方式。

1.2 背景与机会

  • 麦当劳官方开放 MCP（open.mcd.cn），覆盖点餐全流程、优惠券、积分商城等 30+ 工具；
  • 同类参赛项目 100+，榜首集中在「省钱工具」与「卡路里计算」，均缺少"懂人"的维度；
  • 用餐赛道命题是"把今天吃什么交给 AI"——情绪化输入（"好烦啊"）恰恰是最真实的用户表达，现有项目接不住。

1.3 差异化主张

省钱助手们

只算账，不懂人。优惠在本产品中只是"宇宙没善待你，但优惠券有"的彩蛋。

营养助手们

只算热量，冷冰冰。营养在本产品中是叙事素材，不是指标。

普通推荐助手

无记忆、无知识层。本产品有跨会话记忆 + 节气/星座知识，越用越懂你。

本产品护城河

登录 + 记忆：账号绑定个人记忆库，第二次对话即暴露差异；情绪输入接得住，明确指令也算得准。

03用户账号体系（仅麦当劳 Token 登录）

核心设计：Token 即身份，即授权。不设手机号、微信等其他登录方式。用户粘贴麦当劳 MCP Token 即完成「登录 + 授权 + 身份确认」三件事：Token 天然绑定个人会员账号，零短信依赖（自部署友好），登录后 AI 可直接以该账号建单，支付时把链接交给用户即可。

3.1 账号能力总览

能力说明优先级
麦当劳 Token 登录（唯一方式）粘贴 MCP Token → 服务端调 now-time-info 验证有效性（401 拒绝并提示）→ 派生 user_id（SHA-256 前 16 位）→ 签发 JWT 会话。登录即完成麦当劳账号授权。必须
Token 申请引导没有 Token？页内展示三步指引（open.mcd.cn 扫码登录 → 控制台激活 → 复制 Token）并附跳转链接必须
访客模式（先玩后登录）未登录可体验 1 次对话（记忆不保存），结束引导："粘贴你的麦当劳 Token，让我真正记住你，还能直接帮你下单"必须
首次引导三连问昵称、生日（自动推星座）、忌口/过敏——Token 不携带这些资料，首次登录补齐，同时完成记忆冷启动必须
退出登录 / Token 解绑退出仅清会话；解绑则删除服务端加密 Token 与全部记忆数据必须
记忆管理页查看/修改/删除 AI 记住的内容（透明化，隐私即卖点）应该

3.2 关键规则

  • 身份派生：user_id = SHA-256(token) 前 16 位——同一 Token 永远映射同一记忆库，换设备粘贴同一 Token 即找回全部记忆，跨设备同步天然成立。
  • Token 加密存储：服务端 AES 加密落库，仅调用麦当劳 MCP 时解密使用；前端不缓存、日志脱敏（仅显示前 4 后 4 位）。
  • 强制 HTTPS：Token 等同账户凭证，全站 HTTPS 为部署硬性要求。
  • 失效自愈：MCP 返回 401 → 会话失效，引导重新粘贴新 Token（可在 open.mcd.cn 重新生成）；返回 429 → 降级用缓存菜单回复。
  • 风险明示：登录页提示"Token 等同登录凭证，请勿分享"；产品仅支持单人单 Token，不做代点他人账号。
  • 访客转正：访客对话中的一次性偏好（"不要辣"）在 Token 登录后并入其记忆。

3.3 登录页交互要点

  • 主态 = Token 输入框（掩码显示，支持粘贴）+「连接麦当劳」按钮，文案点题："一个 Token，让它认识你"；
  • 校验失败（401）提示："这个 Token 失效了，去 open.mcd.cn 重新生成一个"；
  • 登录成功 → 三连问引导（称呼/生日/忌口）→ 进入对话；
  • 登录页明示权益："登录后可以直接帮你下单，最后一步扫码付款即可"。

05产品架构：六层流水线

在原五层之前新增「身份与记忆存取层」，记忆读写全部经过账号校验。

⓪ 身份层 登录态校验（JWT）→ 加载 memory/{user_id}.json（访客则用临时上下文） ↓ ① 多维意图解析（三路信号并行，不互斥） ├─ 显式指令：人数 / 预算 / 忌口 / 取餐方式 / 时间 ├─ 情绪信号：语气、关键词（烦/累/爽/emo/庆祝） └─ 隐式上下文：当前时段、日期节气、用户记忆 ↓ ② 知识引擎 节气历（24 节气→食物意境）× 星座库（星座/水逆→策略）× 时段感（早/午/下午茶/夜市） ↓ ③ MCP 现实校准 query-meals（时段可售）→ query-meal-detail（特制 modification） → list-nutrition-foods（营养叙事）→ available-coupons（优惠惊喜） → calculate-price（预算校验） ↓ ④ 输出生成 懂你开场 + 完整菜单列表（主推/替换/特制/券后实付/热量一句话）+ 情绪收尾（记忆回钩） ↓ ⑤ 交易闭环 用户确认 → calculate-price 复核 → create-order（返回支付链接，用户付款）→ 记忆更新落盘

FR-2 多维意图解析 P0

  • 显式约束抽取为结构化字段：{人数, 预算, 忌口[], 口味[], 取餐方式, 期望时段}；
  • 情绪分类映射到 6 种基本状态：烦躁 / 疲惫 / 低落 / 开心 / 平淡 / 庆祝，各自对应口味策略（甜/辣/冰/热/碳水/仪式感）；
  • 情绪不明确时允许反问一次（"听起来是累还是气？"）——反问本身是情绪价值；
  • 三类信号可叠加：明确指令 + 附带情绪（"加完班好累，帮我点 2 人份"）全部生效。

FR-3 用户记忆系统 P0（护城河）

模块字段更新时机

口味画像 taste甜度/辣度/温度偏好、常点单品 Top5、特制习惯（去冰等）每次下单后自动归纳
习惯数据 habits历史点单、预算区间、常去时段、常去门店每次交易后追加
情绪日记 mood_diary日期、情绪、当时推荐/点了什么、后续反馈每次情绪类对话结束
仪式记忆 rituals上个节气吃了什么、水逆起止日、生日提醒节气/星座事件触发

存储：memory/{user_id}.json，追加后摘要去重；管理页可视化；访客上下文用完即弃。

FR-4 知识引擎 P0

知识库内容示例
节气历24 节气日期区间 → 食物意境映射小暑→冰激凌"以热制热"；霜降→热可可/板烧"贴秋膘"；冬至→"暖冬套餐"

实现原则：映射表静态规则写死保证演示稳定；回复文案由模型按人设模板生成，保证"每次不一样但不翻车"。

FR-5 MCP 现实校准 P0

限流预案：token 上限 600 次/分钟，菜单数据本地缓存预热，演示控制在 10 轮内。

FR-6 输出规范 P0

  • 懂你开场：结合记忆 + 节气 + 星座 + 情绪，2–3 句，点名"我为什么这么推荐"；
  • 完整菜单：主推套餐 + 可替换项 + 特制建议 + 单价/券后实付 + 热量一句话；明确指令时附预算达成情况；
  • 情绪收尾：金句 + 记忆回钩（"上周三你也是烦躁，点了麦麦鸡——本命解药"）；
  • 行动区：「确认下单」「换一换」按钮；确认后复述菜单与总价再建单；
  • 回复整体可一键生成长图分享。

07交互流程与安全边界

  • 直下单（Token 登录红利）：登录后 AI 以用户会员账号直接调用 create-order 建单——菜单确认后无需任何跳转授权，下单环节全自动；下单后可用 query-order 实时播报出餐进度；
  • 建单确认制：create-order 前必须完整复述菜单 + 价格 + 取餐方式并获用户明确确认（可提供"免确认一键下单"开关，默认关闭）；
  • 付款归属人（平台边界）：MCP 只返回支付链接，支付必须由用户完成——Agent 无法也不应代付，这是麦当劳平台的责任设计，也是产品安全边界；
  • 领券确认制：auto-bind-coupons 前口头确认；
  • 隐私红线：Token 与记忆加密存储；解绑即删；开源仓库绝不包含任何凭证与用户数据；
  • 情绪安全：识别到极端低落表述时，回复切换为温和关怀模式，不使用玩梗文案。

08技术与部署架构（自部署）

前端（可先上线）

纯静态 HTML/CSS/JS，零依赖，本仓库 demo/index.html 即样式基线；部署到任意静态服务器（Nginx / OSS / Vercel）。

后端（接入功能时）

轻量服务（Node/Python 均可）：Token 登录与 JWT、记忆 CRUD（SQLite/JSON）、MCP 代理调用（token 服务端解密持有）。无短信等第三方依赖。

AI 编排

LLM 按人设模板生成回复；意图解析与知识映射用规则表保证稳定，模型只做润色。

MCP 接入

Streamable HTTP → https://mcp.mcd.cn，Authorization: Bearer；生产环境由后端代理调用，前端不接触 token。
部署红线：前端与开源仓库不出现任何真实 token；用户麦当劳 token 加密入库；强制 HTTPS；日志脱敏（token 仅显示前 4 后 4 位）。

12验收标准

  1. 未登录访客可完成 1 次完整对话，结束后出现 Token 登录引导；
  2. 粘贴有效 Token 登录 → 三连问引导 → 记忆冷启动数据落库；无效 Token（401）被拒绝并给出申请指引；
  3. 输入"我好烦啊"（霜降/天蝎座/夜市时段）→ 返回含节气、星座、记忆回钩的情绪回复 + 真实可售菜单 + 券后价；
  4. 输入"明天中午 4 个人，预算 150，有人不吃辣" → 菜单满足全部约束且总价 ≤150；
  5. 退出后重新登录，回复中正确引用上次会话信息（记忆跨会话）；
  6. 确认下单流程：菜单确认 → AI 以用户账号自动建单 → 返回支付链接 → 用户扫码付款 → query-order 播报进度，全程无自动支付；
  7. 记忆管理页可查看并删除任意记忆条目；
  8. 开源仓库经 grep 检查无任何真实凭证。
